AIDLC-WORKFLOWS / CONCEPTS

方法論モデル　AI-DLC が定める 5 フェーズ 32 ステージ

AI-DLC は AI 支援開発を 5 フェーズ・32 ステージへ構造化する AWS 発の方法論である。各ステージの末尾に人間の承認ゲートが立つ。このリポジトリはその公式実装で、方法論が「何を」、ハーネス配布が「どう」を担う。このページは方法論側の概念モデルを、v2 の実装語彙（space / intent / scope / unit / bolt）とともに整理する。

なぜ構造化するか　アドホック AI コーディングの 3 つの破綻

README は問題を 3 点に絞る。プロンプト間で文脈がドリフトする、意思決定の理由が残らない、モデルが頼んでいないことを静かに実行する。AI-DLC の答えも 3 つ対応する。各ステージに責任者（lead agent）を置き、すべての決定を承認ゲートに通し、ユーザーの修正を永続ルールとして記録する。同一エンジンが使い捨ての PoC も規制産業の案件も駆動する。変わるのは実行するステージ数と深度だけである。

出典: README.md docs/guide/00-introduction.md

方法論そのものは 7 つの原則に圧縮されている。置き場所は共有ナレッジの冒頭で、全エージェントが毎ステージ読み込む。ゲート・スコープ・標準化された完了メッセージ・矛盾検出という設計判断は、すべてこの 7 行に遡る。なお、これは方法論仕様の 9 原則（Specification PDF 由来の設計思想）とは別物で、こちらは実行時に守る運用原則にあたる。

パスの注意 原則 3 の aidlc-docs/ は v1 由来の旧表記。v2 の実行時パスは aidlc/spaces/<space>/intents/<YYMMDD>-<label>/（record dir）で、詳細は実行モデルで扱う。

ライフサイクル　5 フェーズ・32 ステージ

ライフサイクルは INITIALIZATION（3）→ IDEATION（7）→ INCEPTION（8）→ CONSTRUCTION（7）→ OPERATION（7）の 32 ステージで進む。フェーズ境界のうち 3 箇所に検証ゲートが入り、トレーサビリティを検査する。対象は Ideation→Inception、Inception→Construction、Construction→Operation である。終端の 4.7 を承認するとワークフローが完了するか、1.1 へ戻る反復ループに入る。

フェーズステージ目的出口
INITIALIZATION（0.x）3ブートストラップ（record dir 作成、greenfield/brownfield 判定、状態ファイル生成）自動遷移（承認ゲートなし）
IDEATION（1.x）7構想の妥当性検証（意図・市場・実現性・スコープ・チーム）承認済み initiative brief
INCEPTION（2.x）8要求の精緻化（要件・ストーリー・設計・Unit 分解・デリバリー計画）実行計画（bolt-plan.md）
CONSTRUCTION（3.x）7構築（機能設計・NFR・インフラ・コード・テスト・CI）動作しテスト済みのコード
OPERATION（4.x）7デプロイと運用（パイプライン・環境・可観測性・インシデント・改善）監視付きの本番システム

実行トポロジーは 28 ステージが inline で、分散実行はわずか 4 ステージである。inline では conductor がエージェント人格を纏い、対話の中で実行する。分散する 4 つは 3 形態に分かれる。2.2 practices-discovery と 3.5 code-generation は subagent である。2.1 reverse-engineering は 2 リンクの pipeline、2.4 user-stories は mob になる。mob ではリードが草稿を書き、互いに盲目な協力者が並列に contribution を書き、リードが統合する。

参照: core/aidlc-common/stages/（32 ステージの正） docs/guide/04-phases-and-stages.md stage-graph.json（コンパイル済みグラフ）

Bolt と walking skeleton　Construction の実行単位

Construction は「Bolt ごと」に走る。Bolt は 1 つの Unit に対する 3.1–3.5 の 1 パスである（依存で結ばれた小さな Unit 群も 1 Bolt にまとめる）。最初の Bolt は walking skeleton、つまりアーキテクチャを end-to-end で証明する最小スライスにあたり、ゲート付きで対話的に実行される。skeleton の承認直後に ladder prompt が 1 回だけ発火する。「以降を自律実行するか、Bolt ごとにゲートするか」の選択が状態に記録され、残り全 Bolt を統べる。この形に至った経緯はガイドに明記されている。

自律モードでも止まる箇所が 1 つだけある。Bolt のコード生成が失敗したとき、ワークフローは autonomy 設定にかかわらず必ず停止し、Retry / Skip / Abort を提示する（halt-and-ask）。失敗した worktree は保全され、判断は常に人間に返る。

参照: core/aidlc-common/protocols/stage-protocol.md（halt-and-ask 規定）

概念モデル（用語）

v2 の語彙は 4 群に分かれる。「どこで作業するか」が workspace / space / intent、「何を実行するか」が stage / scope / depth / unit / bolt である。「誰が動かすか」が engine / conductor / agent、「何が品質を守るか」が gate / sensor / rule / audit / learnings にあたる。

スコープと深度　同じエンジン、違う量

スコープは 32 ステージの EXECUTE/SKIP 行列である。bugfix は 7 ステージまで削り、enterprise は 32 全部を Comprehensive 深度で回す。bugfix の内訳は初期化 3 に reverse-engineering / requirements-analysis / code-generation / build-and-test を足したものになる。深度は別の軸で、実行するステージを選ばず「各ステージがどれだけ詳細に作るか」を変える。テスト戦略も同じく独立の軸で、3 段階を持つ。

スコープEXECUTE / 32既定深度想定用途
enterprise32Comprehensive規制・大規模。全ステージ + 全部の重み
feature32Standard既定スコープ。全ステージを標準の重みで
workshop25Standard（テストのみ Minimal）ファシリテーター主導の演習。Ideation 7 つを全部スキップ
mvp22Standard市場調査・チーム編成・Operation 全 7 つをスキップ
infra13Standardインフラ専業。ストーリー・モックアップ系を持たない
security-patch10MinimalNFR 要件 + デプロイ 2 ステージを含む最短修正
poc / refactor8Minimal検証・整理の最小構成（refactor は + functional-design）
bugfix7Minimal最小。意図確認すらスキップし再現から入る

スコープはコマンドで明示指定するほか、自由文の意図からキーワードで自動判定できる。/aidlc compose を使えば既成の 9 択にも頼らない。composer エージェントが実装エントロピーを 5 成分でスコアし、最小構成の EXECUTE/SKIP 行列をその場で組む。

参照: core/scopes/（9 スコープの正） scope-grid.json（コンパイル済み行列） docs/guide/05-scopes-and-depth.md

対話モードと承認ゲート

ステージ中の入力方法は 3 モードある。Guide Me は構造化質問に 1 問ずつ答え、Edit File は空欄付きの質問ファイルを直接編集し、Chat は自由対話から決定事項を抽出して書き戻す。どれを選んでも同じ questions ファイルに収斂するので、途中で切り替えても進捗を失わない。

承認ゲートは Initialization を除く全ステージの末尾に立つ。選択肢は Approve / Request Changes の 2 択である。「次のステージ」の表示名はエンジンが計算するので常に正しい。承認には実際の人間のターン（HUMAN_TURN 監査イベント）が要るため、autopilot のモデルが承認を偽造することはできない。reject が 3 回続くと第 3 選択肢 Accept as-is が現れ、現版をアーカイブして先へ進める。Ideation / Inception のゲートに限り、スコープでスキップされたステージをその場で追加する選択肢も出る。

参照: docs/guide/07-interaction-modes.md

ゲートの強制力はプロトコル文書とフックの両方で担保される。仕組みの詳細は実行モデル、レビュアー・センサー・学習ループとの重なりはエージェントと検証を参照。
