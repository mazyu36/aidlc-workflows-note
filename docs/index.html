AI-DLC Workflows v2 — コードベースアトラス

awslabs/aidlc-workflows の v2 ブランチを「1 クリックで実コードに届く」形で解説するノート。AI-DLC は AI 主導開発を承認ゲート付きの反復可能なフェーズへ構造化する AWS 定義の方法論で、このリポジトリはその公式実装 — 単一の core/ から Claude Code / Kiro CLI / Kiro IDE / Codex CLI / opencode の 5 配布物を生成する。

TL;DR

設計の要は 3 つの分離。第一に方法論と実装の分離 — 5 フェーズ・32 ステージの方法論は Markdown で記述され、routing は決定論エンジン（TypeScript / bun）が、実行品質は LLM（conductor）が担う。第二にソースと配布の分離 — 手書きの正は core/ の 1 箇所で、5 ハーネス向け dist/ はすべて生成物としてコミットされる。第三に判断と記録の分離 — 承認できるのは人間だけ、状態を書けるのは専用ツールだけで、この壁はフックが機械的に強制する。

リポジトリの三層構造

手書きの正（core/ + harness/）→ パッケージャ（scripts/package.ts）→ コミット済み生成物（dist/）の一方通行。dist を書き換える PR は CI の --check が落とす。テストは 347 ファイルで、TUI・SDK・ACP の 3 方式で実ハーネスを駆動する e2e まで持つ。

core/ # 正: stages 32 / agents 14 / hooks 13 / tools 30 / knowledge 59 / scopes 9 / sensors 4 harness/ # 5 ハーネスの投影レシピ（manifest.ts）+ adapter dist/ # 生成物（コミット済み・--check でドリフト検知）: claude / codex / kiro / kiro-ide / opencode / plugins plugins/ # サンプルプラグイン test-pro scripts/ # package.ts（パッケージャ）ほか docs/ # 公式ドキュメント 91 md（guide 37 / harness-engineering 11 / reference 41） tests/ # 347 テストファイル（smoke / unit / integration / e2e）
