# AI-DLC Workflows 2.0 - ロードマップ

2026-07-13 時点のステータス。現在のリリース版: **2.3.4**（origin/v2 tip 3c768787）。
Full GA は **2.4.0** で宣言される。

## North Star（参照）

AI-DLC Workflows 2.0 North Star の 7 つの機能ゴール。意図を忠実に写す:

1. **実世界での実践の模倣** - 構成可能なアンサンブル（Owner・Collaborator・Verifier）が実行する stage を、harness 横断で一貫した意味論のもとで実現する。
2. **振る舞いのカスタマイズ** - 新しい振る舞い・ポリシー・制約を、狙いを絞った 2 箇所以内の変更でエンコードでき、ツール固有の書き直しなしに harness 横断で再利用できる。
3. **ワークフローの適応性** - スケールイン（レポートのトリアージを Fix・Test・PR に圧縮）とスケールアウト（境界で次の stage 群を決定）。構成はハードワイヤしない。
4. **真の敵対者としての Verifier** - 敵対的な品質 gate。producer と異なる LLM を使ってよい。機械検証可能な証拠に対して検証する。予算付きの自己修復ループが HITL へエスカレーションする。
5. **循環的・方向付きフローのサポート** - 前進の進行に加えて、統制された方向付きフィードバックループ。
6. **成果物トレーサビリティの保持** - 下流 stage は、切り離された成果物を生むのではなく上流の成果物を豊かにする。
7. **プロジェクトローカルでない、組織の成果物リポジトリ** - プロジェクト・intent・リポジトリを横断する共有の組織ナレッジ層。6 つの名前付きシナリオ。

## 未着手（計画済みマイナー）

### 2.4.0 - Verifier としての reviewer（Full GA を宣言）

解釈は 2026-07-13 に確定: **プロンプトのみの変更**。ゴール 4 の 4 文のうち、
「異なる LLM」は提供済み（2.3.1 の tier 分離）、予算も提供済み
（`reviewer_max_iterations` + HITL エスカレーション。「iterations / tokens」は
or として読む）。残るのは:

- 敵対的フレーミング: refute-not-confirm + 証拠グラウンディングの共有契約を stage-protocol のセクション 12a に一度だけ書き、2 つの reviewer ペルソナ（`aidlc-product-lead-agent`、`aidlc-architecture-reviewer-agent`）にドメインの声を短く 1 行ずつ足す。
- 証拠グラウンディングは第 3 文を取り込む: reviewer は既存の機械チェック（列挙された検証ツール、テスト、lint、typecheck、受け入れ基準、consume した契約）を実行する。意見のみの指摘は提案であって NOT-READY ではない。
- 明示的にスコープ外: トークン予算、専用のドメイン検証ツール、新しい stage スキーマのフィールド。これらのスコープ判断は changelog エントリに記録する。
- 新しい agent は作らない: 既存の 2 reviewer が reviewer 宣言のある全 11 stage をカバーする。stage 単位の `reviewer:` フィールドは後から追加できる形になっている。

### 2.5.0 - 3 ロールのアンサンブル（ゴール 1）

- Collaborator を、conductor が inline で纏う声ではなく独立した subagent にする。
- コラボレーションパターン（pipeline / swarm / review-loop / mob）を stage 単位で選択可能なノブにする。

### 2.6.0 - 統制された循環フロー（ゴール 5）

- stage 間の後方エッジ: 下流 stage が上流のギャップを露見させたとき、統制された engine 管理の巻き戻しを発火する。今日のグラフコンパイルはすべてのサイクルを拒否し、`requires_stage` は前方のみ。

### 2.7.0 - 漸進的エンリッチメント（ゴール 6）

- 下流 stage が、リンクされた別ファイルを出すのではなく、同じ上流成果物をその場で豊かにする。
- ADR を core の設計成果物にする。

## マイナーのはしごに載っていない既知のギャップ

- rules の強制（#495）: `rules_in_context` のパスは出力されるが、conductor に読ませる強制が無い。実行時にゴール 2 を静かに損なう。
- stage レベルの rules 層（`aidlc-stage-<slug>.md`）: 予約済み・未実装（ゴール 2）。
- plugin の未提供サーフェス: agents / scopes / memory / knowledge の投影、`when:` の評価、マーケットプレイス（ゴール 2）。
- sensor のブロッキング重大度（#431): sensor は助言のみで、機械チェックが gate を止めることはできない（ゴール 4 に隣接。2.4.0 からは意図的に外す）。
- conductor の健全性クラスタ（#547, #548, #551）と Kiro IDE 1.0 クラスタ（#543, #555）: GA 前の品質であり、ゴールには対応しない。両方の IDE issue は依然 OPEN である: 2.5.10 で #555 のフック登録側（v2 schema）が出荷され、2.5.12 で #543 のコンテキストチャネルが出荷されたが、#555 の agent / settings サーフェスは未対応のままである。これらの issue は手動でクローズする必要がある — `v2` を対象とする PR の `Fixes` トレーラーでは自動クローズされない。
- unit 横断のディスカバリー伝播（ゴール 6）: 依然として実在する v2 のギャップだが、唯一のオープン PR（#300）は退役した v1 ツリー（`aidlc-rules/`、base main、2026-05）を対象にしている。rebase ではなく v2 での新規実装が必要。
